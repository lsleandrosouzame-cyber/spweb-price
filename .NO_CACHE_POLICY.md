# 🚫 POLÍTICA ANTI-CACHE - REGRA IMUTÁVEL

## ⚠️ REGRA PRINCIPAL E IMUTÁVEL

**NADA PODE FICAR EM CACHE. TUDO DEVE SER GRAVADO E SALVO NO SUPABASE.**

Esta é a regra fundamental e imutável do sistema SPWeb Lucro. Todos os dados devem ser:
- ✅ Lidos diretamente do Supabase em tempo real
- ✅ Salvos imediatamente no Supabase
- ❌ NUNCA armazenados em localStorage
- ❌ NUNCA armazenados em sessionStorage
- ❌ NUNCA cacheados pelo navegador ou servidor

---

## 📋 Implementações Aplicadas

### 1. **HTML (index.html)**
```html
<meta http-equiv="Cache-Control" content="no-cache, no-store, must-revalidate" />
<meta http-equiv="Pragma" content="no-cache" />
<meta http-equiv="Expires" content="0" />
```

### 2. **Vite Config (vite.config.ts)**
```typescript
server: {
  headers: {
    'Cache-Control': 'no-store, no-cache, must-revalidate, proxy-revalidate',
    'Pragma': 'no-cache',
    'Expires': '0',
  },
}
```

### 3. **Servidor Node.js (server.mjs)**
```javascript
const cacheControl = 'no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0'
```

### 4. **Apache (.htaccess)**
Configuração completa para desabilitar cache em todos os arquivos.

### 5. **Netlify/Vercel (_headers)**
Headers de cache-control para deploys serverless.

## 🔒 Garantias

1. **Dados sempre frescos**: Usuário sempre vê dados atualizados do Supabase
2. **Sem conflitos**: Não há risco de dados antigos sobrescreverem dados novos
3. **Sincronização perfeita**: Múltiplos dispositivos sempre mostram os mesmos dados
4. **Auditoria completa**: Todo histórico no Supabase (pricing_history)

---

## 🚨 ATENÇÃO PARA DESENVOLVEDORES

- ❌ NÃO adicione `localStorage.setItem()` em lugar algum
- ❌ NÃO adicione `sessionStorage.setItem()` em lugar algum
- ❌ NÃO use bibliotecas que façam cache automático sem revisão
- ✅ SEMPRE consulte o Supabase para dados
- ✅ SEMPRE salve no Supabase imediatamente
- ✅ Use `useEffect` + `refresh()` para dados em tempo real

---

## 📝 Checklist para Novos Recursos

Ao adicionar um novo recurso, garanta:

- [ ] Dados são lidos do Supabase (não de estado local persistido)
- [ ] Dados são salvos no Supabase imediatamente após mudança
- [ ] Não há uso de localStorage/sessionStorage
- [ ] Não há cache de API responses
- [ ] Refresh automático após operações de escrita
- [ ] Headers HTTP corretos (no-cache) para novas rotas
